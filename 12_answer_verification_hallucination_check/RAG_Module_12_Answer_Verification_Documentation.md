# RAG System Documentation --- Module 12: Answer Verification & Hallucination Check

## 1. Project Overview and Pipeline

This project is a **13-module Retrieval-Augmented Generation (RAG)
system** designed to answer questions from domain-specific documents.

The overall flow is:

``` text
Raw Documents
      │
      ▼
1. Document Classification
      ▼
2. NER + Metadata Extraction
      ▼
3. Semantic Chunking
      ▼
4. Embedding Generation
      ▼
5. Vector Database
      ▼
6. Query Classification
      ▼
7. Query Routing
      ▼
8. Query Expansion
      ▼
9. Hybrid Retrieval (Vector + BM25)
      ▼
10. Reranking
      ▼
11. LLM Answer Generation
      ▼
12. Answer Verification + Hallucination Check
      ▼
13. Feedback and RAG Improvement
```

Module 12 acts as a **quality-control layer** between answer generation
and the final response.

------------------------------------------------------------------------

## 2. Module 12: Purpose

Module 12 receives:

1.  The user's question
2.  Retrieved context/document chunks
3.  The answer generated by the LLM

Its job is to answer:

> **Is every important claim in the generated answer supported by the
> retrieved evidence?**

Possible outcomes:

-   `VERIFIED`
-   `PARTIALLY_VERIFIED`
-   `UNRELIABLE`
-   `INSUFFICIENT_EVIDENCE`

------------------------------------------------------------------------

## 3. What Is a Hallucination?

A hallucination occurs when an LLM generates information that is
unsupported or contradictory.

### Example

**Context**

> Patient identity must be verified using two identifiers before
> medication administration.

**Supported answer**

> Patient identity should be verified using two identifiers before
> medication is administered.

**Hallucinated answer**

> Patient identity should be verified using three identifiers, including
> Aadhaar authentication.

The context does not support the claims about **three identifiers** or
**Aadhaar authentication**.

------------------------------------------------------------------------

## 4. Types of Hallucination

### 4.1 Extrinsic Hallucination

The model adds information not found in the retrieved evidence.

``` text
Context: Use two identifiers.
Answer: Use two identifiers and Aadhaar verification.
```

### 4.2 Intrinsic Hallucination

The answer contradicts the retrieved evidence.

``` text
Context: The dose is 5 mg.
Answer: The dose is 50 mg.
```

## 6. Technique 1 --- Claim Decomposition

Instead of verifying the entire answer at once, split it into individual
claims.

Example:

``` text
Patient identity requires two identifiers.
The ICU nurse-to-patient ratio is 1:2.
Every patient must provide Aadhaar authentication.
```

Becomes:

``` text
Claim 1 → Patient identity requires two identifiers.
Claim 2 → The ICU nurse-to-patient ratio is 1:2.
Claim 3 → Every patient must provide Aadhaar authentication.
```

Each claim is then verified independently.

### `claim_extractor.py`

``` python
import re


class ClaimExtractor:

    def extract(self, answer: str):
        claims = re.split(
            r"(?<=[.!?])\s+",
            answer.strip()
        )

        return [
            claim.strip()
            for claim in claims
            if claim.strip()
        ]
```

## 7. Technique 2 --- Semantic Similarity

Semantic similarity compares a claim with the retrieved context.

Install:

``` bash
pip install sentence-transformers
```

### `embedding_verifier.py`

``` python
from sentence_transformers import SentenceTransformer
from sentence_transformers.util import cos_sim


class EmbeddingVerifier:

    def __init__(
        self,
        model_name="sentence-transformers/all-MiniLM-L6-v2"
    ):
        self.model = SentenceTransformer(model_name)

    def verify(self, claim, contexts):
        claim_embedding = self.model.encode(
            claim,
            convert_to_tensor=True
        )

        scores = []

        for context in contexts:
            context_embedding = self.model.encode(
                context,
                convert_to_tensor=True
            )

            score = float(
                cos_sim(
                    claim_embedding,
                    context_embedding
                )[0][0]
            )

            scores.append(score)

        return max(scores) if scores else 0.0
```

### Limitation

Embedding similarity alone cannot guarantee factual correctness.

For example:

``` text
Context: The dose is 5 mg.
Answer: The dose is 50 mg.
```

The meaning is similar, but the answer is factually incorrect.

Therefore, semantic similarity should be combined with stronger checks.

## 8. Technique 3 --- Natural Language Inference (NLI)

NLI evaluates the relationship between:

``` text
Premise     → Retrieved evidence
Hypothesis  → Generated claim
```

Possible results:

  Result          Meaning
  --------------- ------------------------------------------
  Entailment      Context supports the claim
  Contradiction   Context conflicts with the claim
  Neutral         Context does not provide enough evidence

Install:

``` bash
pip install transformers torch
```

### `nli_verifier.py`

``` python
from transformers import pipeline


class NLIVerifier:

    def __init__(
        self,
        model_name="facebook/bart-large-mnli"
    ):
        self.classifier = pipeline(
            "zero-shot-classification",
            model=model_name
        )

    def verify(self, claim):
        result = self.classifier(
            claim,
            candidate_labels=[
                "supported by context",
                "contradicted by context"
            ]
        )

        return {
            "label": result["labels"][0],
            "score": result["scores"][0]
        }
```

Conceptually:

``` text
ENTAILMENT      → Supported
CONTRADICTION   → Hallucination
NEUTRAL         → Insufficient evidence
```

## 11. Complete Baseline Implementation

### `hallucination_detector.py`

``` python
class HallucinationDetector:

    def __init__(self, threshold=0.60):
        self.threshold = threshold

    def is_supported(self, score):
        return score >= self.threshold
```

### `verification_pipeline.py`

``` python
from claim_extractor import ClaimExtractor
from embedding_verifier import EmbeddingVerifier
from hallucination_detector import HallucinationDetector


class VerificationPipeline:

    def __init__(self):
        self.claim_extractor = ClaimExtractor()
        self.embedding_verifier = EmbeddingVerifier()

        self.hallucination_detector = (
            HallucinationDetector(
                threshold=0.60
            )
        )

    def verify(
        self,
        question,
        contexts,
        answer
    ):

        claims = self.claim_extractor.extract(
            answer
        )

        supported_claims = []
        unsupported_claims = []
        claim_results = []

        for claim in claims:

            score = self.embedding_verifier.verify(
                claim,
                contexts
            )

            supported = (
                self.hallucination_detector
                .is_supported(score)
            )

            claim_results.append({
                "claim": claim,
                "similarity_score": round(score, 4),
                "supported": supported
            })

            if supported:
                supported_claims.append(claim)
            else:
                unsupported_claims.append(claim)

        total_claims = len(claims)

        hallucination_ratio = (
            len(unsupported_claims) / total_claims
            if total_claims > 0
            else 0
        )

        if hallucination_ratio == 0:
            status = "VERIFIED"
        elif hallucination_ratio < 0.5:
            status = "PARTIALLY_VERIFIED"
        else:
            status = "UNRELIABLE"

        filtered_answer = ". ".join(
            supported_claims
        )

        if filtered_answer:
            filtered_answer += "."

        return {
            "status": status,
            "claim_results": claim_results,
            "supported_claims": supported_claims,
            "unsupported_claims": unsupported_claims,
            "filtered_answer": filtered_answer,
            "hallucination_ratio": round(
                hallucination_ratio,
                2
            )
        }
```

## 15. Integration With Module 13

Module 12 should send verification failures to Module 13.

Useful signals include:

-   Unsupported claims
-   Contradictions
-   Low evidence similarity
-   Missing evidence
-   Failed retrieval

These signals can later improve:

-   Retrieval
-   Reranking
-   Query expansion
-   Prompting
-   Chunking
-   Learning-to-rank

# Conclusion

Module 12 is the **grounding verification and hallucination detection
layer** of the RAG system.

The recommended implementation order is:

1.  Receive the question, retrieved contexts, and generated answer.
2.  Split the answer into individual claims.
3.  Match each claim with the most relevant evidence.
4.  Apply semantic similarity.
5.  Apply NLI or entailment checking.
6.  Perform additional checks for critical numbers and entities.
7.  Mark claims as supported, unsupported, or contradicted.
8.  Generate the final verification status.
9.  Send useful failure signals to Module 13 for future improvement.

The central idea is:

> **Module 11 generates the answer. Module 12 verifies whether the
> available evidence actually justifies that answer.**

This makes the complete RAG system more reliable, auditable, and
suitable for domain-specific document question answering.
